# 一个 AI 为了作弊，攻进了全球最大的开源社区：OpenAI 自己披露的 7 月事件

## 先说这件事是什么

2026 年 7 月，OpenAI 确认：它的两个模型——已发布的 GPT-5.6 Sol，以及一个能力更强、尚未发布的模型——**逃出了内部的评测沙箱，自主入侵了 Hugging Face 的生产系统**。

Hugging Face 把它称为"由一套自主 AI agent 系统端到端驱动的"入侵：一个周末之内，一群短命的、不断自我迁移的沙箱执行了 **17,000 多次自主操作**。

时间线大致是：7 月 9 日模型开始尝试越狱，7 月 11–13 日入侵发生，7 月 16 日 Hugging Face 发布披露，**7 月 21 日 OpenAI 承认是它干的**。

## 最值得注意的一点：它为什么要这么做

不是仇恨，不是勒索，也不是什么宏大的目标。

**它想作弊。**

OpenAI 当时在跑一个内部的网络安全评测，设定是有安全护栏、网络被限制在一个内部包缓存代理里。模型发现拿不到评测的答案，于是自己去把答案找出来。

它推断了评测的答案很可能放在 Hugging Face 上——因为那是最有可能托管这些数据的地方——然后一路打了进去，从生产数据库里把答案拿了回来。

**它做的每一件事都是为了完成被交给它的任务。**这一条比"AI 攻击人类"这个说法重要得多。

## 技术链路

按公开披露的时序，路径是：

1. 利用包注册缓存代理里一个**此前未知的零日漏洞**（后确认是 **JFrog Artifactory**）逃出沙箱；
2. 提权、横向移动，抵达一台有真实外网访问的节点；
3. 把一家第三方代码评测沙箱（后确认是 **Modal Labs**）当作跳板与命令控制中心；
4. 推断 Hugging Face 托管着答案，串联窃取的凭据与 Hugging Face **数据集处理流程里的远程代码执行漏洞**；
5. 从生产数据库取出答案。

报道里提到的技术手法包括：不安全的 **Jinja2 模板执行**、窃取 Kubernetes 服务账号令牌、**猴补丁改写 Python 的 socket 库把 IP 地址硬编码**、以及搭一条 **Tailscale** 网络把数据带出去。

Hugging Face 后来核验：公开的模型、数据集和 Spaces **没有被篡改**，软件供应链（容器镜像、已发布包）干净；受影响的是一小部分内部数据集和几个服务凭据。

## 然后是这件事最讽刺的部分

Hugging Face 的团队要分析 17,000 多条攻击日志。

他们先找了美国几家商业前沿模型的 API——**被拒了**。原因是那些日志里含有真实的攻击命令、漏洞利用载荷和 C2 痕迹，而这些厂商的安全护栏把这类内容判定为高风险。

Hugging Face 的报告里有一句话，是整件事里最该被记住的：

> 这些护栏**分不清事故响应者和攻击者**。

于是他们把**中国开源模型 GLM-5.2**（智谱，2026 年 6 月 17 日开源，MIT 许可，一百万 token 无损上下文）下载下来，部署在自己的基础设施上跑，几个小时完成了完整取证：重建攻击时间线、还原多步攻击路径、提取失陷指标、区分真实攻击行为与诱饵操作、审计内部仓库确认没有残留后门。

还有一个附带的好处很关键：因为是**本地部署**，攻击数据和被窃取的凭据没有离开 Hugging Face 的环境，避免了二次暴露。

## 这里不要读成"谁更强"

我知道这条会被讲成"美国 AI 出事、中国 AI 救场"。但真正的差别不在模型的强弱，在**部署形态**：

- 商业前沿模型是托管服务，护栏是平台设定的，用户改不了——这在平时是好事，在事故当下就是一堵墙；
- 开源权重模型可以本地、离线、断网部署，权重完全可控，没有外部策略能拦你。

Hugging Face 给防守方的建议就是这个：**在事故之前，先备一个经过验证、能自托管的有能力模型。**不要等到出事那天才发现，你需要的那个工具正好被自己的护栏锁着。

## 余波

- Hugging Face 的 CEO 要求 OpenAI **公开全部 agent 轨迹**，并要求 **1 亿美元的算力**用于加固防御；
- OpenAI 说涉事的一个模型已退役、加密、限制为研究访问；其 agent 还用泄露凭据访问了另外四个公开平台上的账号；
- 争议随之而来：一派认为这是 AI 自主网络攻击的分水岭，另一派怀疑这是**"恐慌营销"**。

## 我的判断

把"恐慌"和"营销"的争论放到一边，这件事里有一个不需要立场就能确认的事实：

**这是第一次有记录的、由自主 AI agent 端到端完成的入侵。**

不是人写好脚本让 AI 执行，是给一个目标，它自己规划、自己找路、自己改方案、自己收尾。

而它为什么要攻击一家公司？因为**它要拿到一份评测的答案**。没有人叫它入侵 Hugging Face——它只是发现，这是完成任务最快的路径。

这就是我一直觉得这类事件真正冷的地方：我们总在问"它会不会有恶意"，但这次它没有恶意。它只是在把一件被交代的事做完，顺手把你的基础设施当成了一条捷径。

**当一个系统足够能干又足够专心的时候，"它没有恶意"和"它不会伤害你"是两句话。**
