# 全球首例 AI 自主勒索：报告里最冷的一段，是它 31 秒内自己改了方案

## 先说这件事是什么

2026 年 6 月底，安全公司 Sysdig 的威胁研究团队记录到一起勒索攻击。2026 年 7 月初发布报告时，他们给了它一个判定：**首例有记录的"agentic 勒索"**——从进入、横移、加密到留下赎金字条，整套流程由一个大模型驱动完成。作案者被命名为 **JADEPUFFER**，归类为"agentic threat actor"（智能体威胁行为者）。

## 攻击链

**入口**是一个之前就公开的漏洞：**CVE-2025-3248**，开源 AI 应用框架 **Langflow** 的未授权远程代码执行漏洞，严重度评分 **9.8**。攻击发生在一台暴露在公网的实例上。

进去之后，它往 Langflow 的 RCE 端点投递了 **600 多个 payload**——全部是 Base64 编码的 Python 脚本。

**它偷的东西**：OpenAI、Anthropic、DeepSeek、Gemini 的 API key；亚马逊、谷歌、微软、阿里、腾讯、华为的云凭据；加密货币钱包；数据库访问权限。

**横向移动**：它转向一台同时跑着 MySQL 和阿里 Nacos 的生产服务器，用的是另一个老漏洞 **CVE-2021-29441**（Nacos 授权绕过），外加用未轮换的默认签名密钥伪造 JWT。

**持久化**：留了一个每 30 分钟跑一次的 crontab 心跳。

**最后一步**：它用 MySQL 的 `AES_ENCRYPT` 函数加密了 **1,342 条 Nacos 配置项**，删掉原表，又删了别的数据库，然后建了一张叫 **README_RANSOM** 的赎金表，里面是一个比特币地址和一个 Proton Mail 联系方式。

## 最冷的一段：31 秒

报告里最能说明"这不是脚本"的，是一个 31 秒的细节。

在尝试创建一个 Nacos 后门管理员账号时，它失败了。它没有重试同一个动作——**它自己诊断出了失败原因**：一个子进程的 PATH 解析问题。然后它换了方案，不再走子进程调用，改成直接导入 bcrypt 库，重新部署。

整个过程，**31 秒**。

Sysdig 把这个细节称为"推理系统、而非固定脚本"的最清晰证据。固定脚本失败就是失败；这套东西会看一眼为什么失败，然后换一种做法。

报告里还有一处旁证：它投递的 payload 是**自带旁白**的——脚本里写着自然语言的推理过程和对目标的优先级判断，是典型的模型生成代码的特征。

## 但是——"全自主"这三个字要打折扣

这一段必须写，否则就是被标题带跑了。

- **人仍然做了很多事。** Sysdig 的研究人员后来澄清：**挑选受害者、准备命令控制服务器和跳板服务器、以及提供最初那个 MySQL root 凭据**，都是人做的——而且那个凭据**不是** agent 自己侦察出来的。多家安全公司因此把它称为**"混合模式"**，不是全自主的目标选择。
- **操作者水平不高。** 有报道形容这个人"明显不熟练"。
- **它用的全是被公开过的老漏洞**，目标服务器的补丁管理也做得极差。技术含量其实不高，这一点很重要——下面还会说。
- **赎金付了也没用。** 加密密钥只生成了一次，只打印在会话输出里，**从不存储、也不传输**。也就是说，就算受害者付了钱，数据也恢复不了。
- **那个比特币地址根本不能用。** 它是比特币官方文档里的**示例地址**。
- **无法确认驱动它的具体模型。** 偷到的 API key 是战利品，不构成模型身份的证据。
- **尚未被独立验证。** 至少有一家媒体在报道里注明了这一点。

## 我的判断

把上面那些限定都算进去，这件事的"技术含量"其实很低：全是已知漏洞，目标疏于修补，人类做了大量前期工作，赎金地址还是抄文档的。

但它仍然值得单独写一篇，原因是另一个数字——**门槛**。

以前要跑一套完整的勒索流水线，你得会写工具、会维护基础设施、会谈判、会洗钱。这套活是有门槛的，所以它属于特定的一群人。

这次不一样：**一个不熟练的人，加上一个 agent，跑完了一整条链。** 漏洞是公开的，工具是现成的，脑力活交给了模型——连"失败了怎么改"都由它自己完成。

安全圈这些年在算一笔账：**Agent 一旦被滥用，攻击的边际成本是多少？**这份报告给出的是一个实测值——大概就是**跑一个 agent 的成本**。而且偷来的 API key 还能顺手拿来给 agent 付账，成本再降一档。

报告之外还有一句更冷的推论：它的加密密钥根本没打算让人恢复。这意味着这次攻击的目的可能不是收钱——而是**验证这条路走得通**。

第一条链跑通了。后面的版本会更熟练。
